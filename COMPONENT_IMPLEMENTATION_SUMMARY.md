## Technical Implementation Details

### Architecture Decisions

1. **Error Boundaries:**
   - Each component has its own error boundary
   - Prevents cascade failures in game lists
   - Shows user-friendly error messages
   - Logs errors for monitoring

2. **Performance Optimizations:**
   - `React.memo()` wrapper prevents unnecessary re-renders
   - `useMemo()` for derived values (winner computation, correctness)
   - `useCallback()` for event handlers
   - Minimal state updates

3. **Accessibility:**
   - Semantic HTML with proper ARIA roles
   - Keyboard navigation support
   - Screen reader announcements
   - Focus management
   - Color is never the only indicator

4. **State Management:**
   - Optimistic updates in PickSelector
   - Rollback on error
   - Sync with parent state via useEffect
   - Loading states during async operations

### Icon Usage (from @heroicons/react v2.2.0)

- `CheckIcon` - Selection indicator, correct picks, winner
- `XMarkIcon` - Incorrect pick indicator
- `ArrowPathIcon` - Loading spinner with animation

## Known Limitations

1. **PickSelector:**
   - Does not support undo functionality (can be added if needed)
   - Loading state is per-button (not global)
   - Error messages are inline only (could integrate with toast system)

2. **GameResult:**
   - Does not show live score updates (requires external polling/WebSocket)
   - Winner computation assumes higher score wins (no spread-based winners)
   - Tie games show no winner indicator

3. **Both Components:**
   - No internationalization (i18n) support yet
   - No dark mode variants yet
   - Logo loading failures show abbreviation fallback only
